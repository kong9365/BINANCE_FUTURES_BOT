## ⚠️ 0. 가장 먼저 — 솔직한 현재 상태 (반드시 읽기)

이 봇은 **"돈을 버는 게 증명된 기계"가 아니다.** 지금까지의 모든 백테스트(과거 데이터 시뮬레이션) 결과:

| 검증한 전략 | 결과 |
|---|---|
| 돌파(Phase C) | 비용 전부터 손실(gross −0.242) — 엣지 없음 |
| 델타중립 캐리(D-2) | 비용 차감 후 손실 — net-EV 음수 |
| SMC(스마트머니) | 엣지미달(gross −0.151) |
| 1d 코어(Track B) | 표본부족(n=193) + 비용 전부터 손실(gross −0.084) |

→ **"백테스트로 +EV(기대수익 양수)가 확인된 전략은 아직 없다."** 단 하나 *백테스트로 측정 불가능한*
가설(B-3, §11)만 남았고, 그건 실제 소액 주문으로만 측정된다.

**그래서 이 봇의 정체는 "수익기계"가 아니라 "안전을 최우선으로 한 검증·실험 인프라"다.**
- 실거래 스위치는 기본 **꺼짐(HOLD)**. 운영자가 명시적으로 켜야만 실주문이 나간다.
- 라이브를 켠다면 그건 "수익 기대"가 아니라 **"실행 데이터·경험을 사는 수업료"**라는 전제다.
- 봇 전체가 *"어떻게 돈을 더 버나"*가 아니라 *"어떻게 덜 잃고, 위험하면 즉시 멈추나"*에 맞춰져 있다.

## 1. 큰 그림 — 봇은 "짧은 주기로 도는 점검 루프"다

봇은 켜져 있는 동안 같은 점검 루프(`main_7590.py`의 `_iter`)를 반복한다.
한 바퀴에서 아래를 **위→아래**로 통과해야만 거래가 일어난다. **앞에서 막히면 그 바퀴는 거기서 끝(거래 안 함).**

```
[루프 1바퀴]
0. 🛑 KillSwitch(비상정지) 켜졌나?            → 켜졌으면 즉시 종료
1. 📡 데이터 신선한가? (가격 수신 정상?)
2. ❤️ 시스템 건강한가? (이상 시 전 포지션 안전청산)
3. 💰 잔고 스냅샷 조회 (실패하면 종료 = fail-closed)
   └ (실험모드면) Probe 한도 도달 점검 → 도달 시 KillSwitch
4. 🌡️ 레짐(시장 분위기) 판정: 상승추세/하락추세/횡보/불확실/고변동
5. 📕 이미 보유한 포지션 관리 (청산 조건 점검 — §6)
6. 🚨 BTC 급락(Risk-Off)? → 신규 진입 차단
7. ⛔ 고변동(HIGH_VOL)/거시이벤트? → 신규 진입 차단
8. 🔍 신호 스캔 (어떤 코인 살까? — §2)
9. 🚪 진입 게이트 관문 통과 → 사이징(§3) → 배율(§4) → 주문(§5)
```

핵심 직관:
- **"막는 단계"가 "사는 단계"보다 훨씬 많다.** 사려면 모든 관문 통과, 멈추는 건 한 곳만 걸려도 된다.
- **기존 포지션 관리(5)는 신규 진입 차단(6~7)보다 먼저.** "더 사는 건 막아도 이미 산 건 계속 안전하게 관리."

## 2. 후보 선정 — "어떤 코인을, 어느 방향으로?"

### 2-1. 거래 가능한 코인 목록(유니버스) — `PairWhitelist`
- **Tier(등급)**: Tier 1(BTC/ETH급 대형) / Tier 2(SOL·BNB·XRP) / Tier 3(중형 후보). 보호종목·미등록 = Tier 0(거래 불가).
- **자본 규모별 제한**: Tier 3은 자본 ≥ $3,000, Tier 2는 ≥ $1,000 필요(돈 적으면 위험 등급 차단).
- **품질 필터**: 24h 거래대금 ≥ $1억, 상장 ≥ 30일, 펀딩비 과도 시 제외.
- **🔒 보호종목 6개(BTCUSDT·ETHUSDT·HOLOUSDT·CFXUSDT·LYNUSDT·INJUSDT)**: **어떤 경우에도 거래 안 함**
  (진입·청산·취소 전부 금지) — 운영자 보유 자산이라 봇이 손대면 안 됨. 최우선·영구 차단.

### 2-2. 세 가지 "사냥 방식"(전략) — `ACTIVE_STRATEGY`, 기본 `oi_surge`
**(A) oi_surge — OI(미결제약정) 급증 추종 (기본)**
- **OIScanner**: *OI 변화율 ≥ 5%* **그리고** *|가격 변화율| ≥ 2%* 동시 만족 → 후보. OI 변화 큰 순 **최대 10개**.
- **방향**: 가격 ↑ → LONG, 가격 ↓ → SHORT.
- **OIFilter(위험 등급)**: A_STRONG / B_MODERATE / **C_DANGER(즉시 차단)**.
  C_DANGER = 고변동 / OI 변화 > 50% / 거래대금 < $1,000만 / 추세 역행.
- **QualityGate(품질 점수)**: 레짐별 통과 기준 이상이어야 신호 확정
  (상승 50 / 하락 55 / 횡보 65 / 불확실 60 / **고변동 999=진입 불가**).

**(B) breakout — 1시간봉 돌파**: 종가 > Donchian20 상단 **&** > EMA200 **&** ADX ≥ 25 → LONG(대칭 SHORT).
**(C) daily_tsmom — 1일봉 돌파**: (B)와 동일 논리를 하루봉 기준으로(Donchian20/EMA200/ADX25).

> 💡 셋 다 본질은 같다: **"추세가 분명할 때만, 추세 방향으로. 추세가 아니면(횡보·고변동) 안 산다."**

## 3. 포지션 크기(사이징) — "얼마어치 살까?" (배율과 별개!)

**가장 중요한 개념**: 이 봇에서 **포지션 크기는 레버리지가 아니라 "위험(risk)"으로 정한다.**

### 3-1. 위험 기반 사이징 (기본 0.5%)
- **목표**: "이 거래가 손절(SL)에 닿으면 *내 자본의 0.5%만* 잃는다"가 되도록 크기를 정함.
- **공식(명목가치 notional)**: `명목가치 = 0.5% × 자본 × 진입가 ÷ |진입가 − 손절가|`
- **수량(코인 개수)** = `명목가치 ÷ 진입가` (거래소 규격으로 반올림).

**예시**: 자본 $1,000, 진입 $100, 손절 $98(손절폭 2%)
→ 명목가치 = 0.005 × 1000 × 100 ÷ 2 = **$250**. 수량 = 250 ÷ 100 = **2.5개**.
→ 손절 도달 시 손실 = 2.5개 × $2 = **$5 = 자본의 0.5%** ✅ (의도대로).
→ 손절폭이 넓으면(예 4%) 같은 0.5% 위험을 지키려고 크기가 **작아진다**(명목 $125). 즉 변동성 큰 코인은 자동으로 작게.

### 3-2. 사이징 한도(상한)
- **A1 안전상한**: 위험은 거래당 **0.5%** 를 넘지 않게 강제(Kelly가 더 키우려 해도 깎음).
- **예산 cap**: 사이징에 쓰는 자본 = `min(가용잔고, 예산상한)`. 라이브 기본 **$300** / 실험모드 **$200**.
- **최소 명목가치**: $5 미만이면 주문 안 함(거래소 최소 미달).
- **실험모드(Probe)**: Kelly를 아예 안 쓰고 **고정 0.5%**(연승해도 절대 안 키움, 코드로 강제).

> 💡 한 줄: **크기 = 위험(0.5%)로 결정 → 손절폭이 좁으면 크게, 넓으면 작게. 레버리지는 여기 안 들어간다.**

## 4. ★ 주문 시 배율(레버리지) 선정 방식 — 상세

### 4-1. 레버리지 공식
주문 직전, 봇은 이렇게 배율을 정한다(`main_7590.py`):
```python
pair_tier   = PairWhitelist.get_tier(symbol)            # 코인 등급 (0/1/2/3)
max_lev_tier = RISK_RULES.max_leverage_by_tier[pair_tier]   # 등급별 상한
leverage     = max(1, min(params.max_leverage, max_lev_tier))   # 레짐상한 ∩ 등급상한, 최소 1배
```
즉 **레버리지 = max( 1 , min( 레짐 상한 , 등급 상한 ) )** — **두 상한 중 더 낮은 값**, 단 **최소 1배** 보장.

### 4-2. 두 가지 상한
**① 코인 등급(Tier)별 상한** (`max_leverage_by_tier`)

| 등급 | 상한 | 예 |
|---|---|---|
| Tier 1 | **5배** | BTC/ETH급 대형(유동성 최고) |
| Tier 2 | **3배** | SOL·BNB·XRP |
| Tier 3 | **3배** | 중형 후보 |
| Tier 0 | **0배** | 보호종목·미등록(= 거래 불가) |

**② 레짐(시장 분위기)별 상한** (`REGIME_TRADING_PARAMS[regime].max_leverage`)

| 레짐 | 상한 | 의미 |
|---|---|---|
| TREND_UP(상승추세) | **5배** | 추세 뚜렷 → 더 허용 |
| TREND_DOWN(하락추세) | **5배** | 추세 뚜렷(숏) |
| RANGING(횡보) | **3배** | 방향 불분명 → 축소 |
| UNCERTAIN(불확실) | **3배** | 축소 |
| HIGH_VOL(고변동) | **0배** | 애초에 진입 자체 차단(allow_entry=False) |

### 4-3. 둘 중 "더 보수적인" 값을 택한다
두 상한 중 **낮은 쪽**을 쓰고, 최소 1배를 보장한다. 등급이 안전해도 레짐이 위험하면 줄고, 그 반대도 마찬가지.

**예시 3가지**
| 코인 등급 | 레짐 | 등급상한 | 레짐상한 | 최종 배율 |
|---|---|---|---|---|
| Tier 1 (BTC) | TREND_UP | 5 | 5 | **min(5,5)=5배** |
| Tier 2 (SOL) | TREND_UP | 3 | 5 | **min(3,5)=3배** |
| Tier 1 (BTC) | RANGING | 5 | 3 | **min(5,3)=3배** |
| 어떤 코인 | HIGH_VOL | – | 0 | (진입 차단 — 거래 안 함) |

→ 실제 라이브에서 나오는 배율은 사실상 **1~5배**(보수적). 고배율(10·20·50배) 같은 건 코드상 불가능하다.

### 4-4. ★가장 중요 — "레버리지는 포지션 크기를 정하지 않는다"
초보자가 가장 헷갈리는 부분. 이 봇에서:
- **포지션 크기(명목가치·수량)는 §3의 위험 0.5%로 이미 정해졌다.** 레버리지와 무관.
- 레버리지는 거래소에 **따로** 설정(`futures_change_leverage`)되며, 하는 일은 **증거금(margin)만 바꾼다**:
  - **필요 증거금 = 명목가치 ÷ 레버리지.**
  - 예: 명목가치 $250를 5배로 = 증거금 **$50**만 묶임. 3배로 = 약 **$83** 묶임.
- 즉 **배율이 높다고 더 크게 사는 게 아니다.** 크기는 같고, *자본이 덜 묶일 뿐*(증거금 효율) + 청산가가 멀어진다.

**왜 이렇게?** 일반적으로 "고배율 = 고위험"인 이유는 *고배율로 크기를 키우기* 때문이다.
이 봇은 **크기를 위험(0.5%)으로 고정**했으므로, 배율을 올려도 **손실 위험이 커지지 않는다.**
배율의 실질 효과는 ①증거금 효율(자본 덜 묶임 → 동시에 더 많은 포지션 여지) ②거래소 강제청산선이 멀어짐.

### 4-5. 그래도 안전한 이유 — "강제청산보다 손절이 먼저"
- 진짜 손실 방어선은 거래소 **강제청산(liquidation)**이 아니라 봇이 건 **손절(SL)**이다.
- 손절은 위험 0.5% 지점(예 진입−2×ATR)에 있고, 강제청산은 그보다 훨씬 멀다(저배율일수록 더 멀다).
- 그래서 정상 동작에선 **손절이 항상 먼저 닿아** 손실이 0.5% 안에서 끊긴다. 배율은 그 위험 크기를 바꾸지 않는다.

> 💡 한 줄 요약: **배율 = min(레짐 상한, 등급 상한), 최소 1배(=1~5배). 크기가 아니라 증거금·청산버퍼만 바꾼다. 손실 크기는 손절(0.5%)이 정한다.**

## 5. 매수(진입) 실행 — "관문 통과 후 지정가 주문"

### 5-1. 진입 전 게이트(관문, 순서대로 — 하나라도 걸리면 차단)
1. **PairWhitelist** — 거래 가능? (보호종목·등급·자본 재확인)
2. **RiskManager 8중 검사** (§7) — 일일/누적/월 손실, 연패, 동시보유, 최소잔고, 일일거래 횟수. **조회 실패도 차단(fail-closed)**.
3. **사이징** (§3) — 위험 0.5% 기반 크기.
4. **CostGuard(비용 차감 기대값)** — "수수료·슬리피지 다 빼고도 이득(EV>0)인가?"
   - 수수료 maker 0.018% / taker 0.045% + 등급별 슬리피지 0.5~1.5% 왕복 반영. 표본 < 10건이면 승률 45% 보수 가정. **EV ≤ 0 → 차단.**
5. **레버리지 결정** (§4).

### 5-2. 실제 주문 — `executor.enter_trade` (돈이 나가는 지점)
1. **A5 인가**: `USE_TESTNET=true` 또는 `LIVE_TRADING_ENABLED=true` 아니면 **실주문 거부**(안전 기본값).
2. **KillSwitch 방어**: 비상정지 켜졌으면(조회 실패도) 거부.
3. **Probe 하드실링**: 실험모드 예산 초과면 거부(메인 로직 우회·버그에도 소액 보장).
4. **One-way 모드 확인** → **거래소 규격 정규화**(LOT_SIZE/PRICE/MIN_NOTIONAL).
5. **레버리지 설정**: `futures_change_leverage(symbol, leverage)` (§4의 값).
6. **🎯 진입 = GTX post-only 지정가** — 신호가에 "메이커 전용" 주문. **15초 대기**(1초마다 확인).
   - 15초 안에 안 채워지면 **취소** + `unfilled_signals` 기록(B-3 분석용, §11).
7. **보호주문 설치(체결 시만)**: 손절(STOP)·익절(TP)을 거래소 algo 주문으로(MARK_PRICE 기준, 전량청산형).
   - **손절 설치 실패 → 즉시 강제청산**(무방비 포지션 금지).
8. **거래 기록**: 위가 다 성공한 뒤에만 `trades` DB 기록.

> 💡 핵심: **"체결 확인 + 손절 설치 성공" 후에만 포지션을 인정.** 손절 없는 포지션은 즉시 닫는다.

## 6. 매도(청산) — "정해진 순서로 자동 관리" (`ExitPlanController`)

포지션 보유 중 매 루프마다 아래를 **위→아래** 점검, 먼저 걸리는 조건으로 처리:

| 순위 | 조건 | 동작 |
|---|---|---|
| ① | **시간 스톱** | 보유 시간 초과 시 **전량 청산**. 한도 = 레짐별(추세 120분 / 불확실 90분 / 횡보 60분). |
| ② | **손절(SL) 도달** | **전량 청산**(손실 확정 — 더 큰 손실 차단). |
| ③ | **익절(TP) 도달** | **전량 청산**(목표 도달). |
| ④ | **분할 익절** | 진입가→TP의 **중간(50%)** 도달 시 **포지션 50%만** 청산(이익 일부 확보). |
| ⑤ | **본전 이동(BE)** | 분할 익절 직후 **1회**, 손절선을 **진입가**로 올림(이후 최소 본전). |
| ⑥ | **ATR 트레일링** | 분할 후, 최고가−1.5×ATR(LONG)로 손절선을 **유리한 방향으로만** 따라 올림(이익 보존). |

- **STOP 교체 = "새 것 먼저 만들고 옛 것 취소"(create-first)** — 손절이 잠깐도 비지 않게.
- **reconcile(대조)**: 거래소에서 손절/익절이 먼저 체결돼 포지션이 사라지면 봇이 감지 → DB 정리.

> 💡 의도: **"손실은 빨리 자르고(②), 이익은 일부 확보 후(④) 본전 보장(⑤) 위에서 끝까지 따라간다(⑥)."**

## 7. 리스크 관리 — "다층 끄는 선"

### 7-1. RiskManager 8중 검사 (매 진입 전, 하나라도 걸리면 차단)
| 검사 | 한도 |
|---|---|
| 일일 손실 | ≤ **−1.5%** 차단 |
| 누적 손실(MDD) | ≤ **−15%** 차단(청산 방어선) |
| 연속 손실 | 7회=7일 정지 / 5회=24h / 3회=4h 쿨다운 |
| 월간 손실 | ≤ **−8%** 차단 |
| 동시 보유 수 | 자본별 1~3개 초과 차단 |
| 최소 잔고 | < **$100** 차단 |
| 일일 거래 횟수 | **5회**(레짐별) 초과 차단 |
- **fail-closed**: 위 값 조회 실패 시 → **무조건 차단**(모르면 멈춘다).

### 7-2. KillSwitch(비상정지) = 전면 HALT
- **파일 기반**: `data/KILLSWITCH` 파일 있으면 전면 정지. 운영자만 파일 삭제로 해제.
- **BTC Risk-Off**: BTC 1시간봉 **−1.2% 이상 급락** → 자동 **6시간** 신규 진입 차단.
- 2단계: −1.0% 경고 / **−1.5%·MDD −15% → KillSwitch 자동 발동**.

### 7-3. Probe(실험모드) 자동 정지 5조건 (실험모드일 때만)
- 누적 손실 ≤ **−15%** / 일일 손실 ≤ **−5%** / 연속 손실 **5회** (= 손실 정지)
- 체결 **30 + 미체결 30** / **4주** 경과 (= 데이터 다 모았으니 정상 종료)

### 7-4. 진입 차단 레짐 / 보호종목
- **고변동·거시이벤트**: 신규 진입 금지(단 기존 포지션 청산 관리는 계속).
- **보호종목 6개**: PairWhitelist + executor 이중 차단 → 진입·청산·취소 전부 금지(`protected_symbol_close_blocked`).

## 8. 자본·돈 흐름 (`CapitalManager`)
- **잔고 스냅샷**: 지갑(wallet)·가용(available)·마진(locked)·미실현손익(10초 캐시).
  - 손실·MDD 기준 = wallet_balance, 신규 사이즈 기준 = available_balance.
- **예산 cap**: `min(가용, 예산상한)`(라이브 $300 / 실험 $200, env 조정).
- **현물 접근 금지**(`forbid_spot_access`): 선물 지갑만. 현물 조회 시 에러로 차단(보호자산 격리).
- **일일 시작 자본**: 매일 UTC 00:00 기록 → "오늘 손실" 계산.

## 10. 초보자 용어 사전
- **레짐**: 시장 분위기(상승/하락/횡보/불확실/고변동). 봇은 레짐에 따라 거래 강도·배율을 바꾼다.
- **OI(미결제약정)**: 시장에 열린 선물 포지션 총량. 급증 = 새 자금 유입 신호.
- **Donchian / EMA / ADX / ATR**: 최근 N봉 박스 / 가중평균선(추세) / 추세 강도 / 평균 변동폭.
- **post-only(GTX) 지정가**: 메이커로만 체결(수수료 저렴). 가격이 닿아야 체결 — 안 닿으면 미체결.
- **maker / taker**: 호가 대는 쪽(싼 수수료) vs 즉시 체결(비싼 수수료).
- **슬리피지 / 펀딩비**: 원가와 체결가 차이(비용) / 롱·숏이 주기적으로 주고받는 비용.
- **레버리지(배율)**: 증거금 배율. 이 봇에선 **크기가 아니라 증거금·청산버퍼**만 바꿈(§4-4).
- **명목가치(notional)**: 포지션의 실제 가치(= 수량 × 가격). **위험 0.5%로 결정**(레버리지 무관).
- **증거금(margin)**: 포지션 유지에 묶이는 돈(= 명목가치 ÷ 레버리지).
- **강제청산(liquidation)**: 증거금 부족 시 거래소 강제 종료. 이 봇은 그 전에 **손절(SL)**이 먼저 닿게 설계.
- **MDD / Kelly / R:R**: 최대낙폭 / 최적 베팅공식(여기선 상한으로 축소만) / 손익비.
- **분할TP / BE / 트레일링 / KillSwitch / fail-closed**: 일부 익절 / 손절선을 본전으로 / 이익 방향으로 따라 올림 / 비상정지 / "모르면 막는다".

## 11. 자주 묻는 질문 (FAQ)
- **Q. 켜져 있는데 거래를 안 해요.** → 정상일 수 있다: 신호 없음(추세 아님)/고변동·BTC급락/RiskManager 한도/KillSwitch.
- **Q. 배율은 누가 정하나요?** → 봇이 자동: `min(레짐 상한, 등급 상한)`, 최소 1배(§4). 보통 1~5배. 사람이 안 정함.
- **Q. 배율을 높이면 더 많이 버나요?** → **아니다.** 크기는 위험 0.5%로 고정(§3). 배율은 증거금·청산버퍼만 바꾼다(§4-4).
- **Q. 왜 일부만 팔았나요?** → 분할 익절(⑥). 중간에서 50% 확보 후 본전 보장 위에서 추세 따라감.
- **Q. 보호종목은 왜 안 건드리나요?** → 운영자 자산이라 영구 차단(진입·청산·취소 전부).
- **Q. post-only가 자주 미체결돼요.** → 가격이 빨리 움직이면 지정가에 안 닿음(= B-3 현상). "달아난 신호가 사실 더 좋았는지"를 실주문으로 측정 중. 백테스트로는 못 잼.
- **Q. 지금 실거래해도 되나요?** → **권장하지 않음(HOLD).** +EV 확인 전략 없음(§0). 라이브는 "B-3 실측·경험"이 목적, 소액·안전장치 가동, 운영자 판단으로만.
