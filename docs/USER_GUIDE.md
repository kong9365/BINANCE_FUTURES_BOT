## 1. 먼저 읽어주세요 (경고)

⚠️ **이 봇은 실제 돈으로 자동매매를 하는 프로그램입니다. 손실 가능성이 매우 높습니다.**

학술 연구에 따르면 단타(단기 매매) 트레이더의 **80~97%가 결국 손실로 끝납니다** (Chague 2020, Barber 2014, BIS Working Paper #1087, NYU Stern 2022). 이 봇의 목표는 "큰돈을 버는 것"이 **아니라**, **"잃는 90~97%에 들지 않는 것"** 입니다. 그래서 설계가 매우 보수적입니다 — 거래를 자주 안 하고, 레버리지를 낮게 쓰고, 손실 한도를 엄격히 둡니다.

**핵심 원칙:**
- 실제 돈을 넣기 전에 **반드시 페이퍼(모의) 단계를 거칩니다.** (→ [14장](#14-페이퍼--실전-전환-기준))
- 봇이 손해를 봐도 그건 운영자(당신) 책임입니다.
- 처음에는 잃어도 괜찮은 소액으로만 시작하세요.

## 2. 이 봇이 하는 일

이 봇은 **바이낸스(Binance) 선물 시장에서 USDT-M 무기한 선물을 단타로 자동매매**합니다.

쉽게 말하면:
1. 시장을 30초마다 살펴봅니다.
2. "지금 시장이 어떤 상태인지"(상승 추세 / 하락 추세 / 횡보 / 불확실 / 고변동성)를 판단합니다.
3. 미리 정해둔 조건(거래량 급증, 미결제약정 변화 등)에 맞는 코인을 찾습니다.
4. 여러 안전 검사(품질·리스크·비용)를 통과하면 포지션을 엽니다.
5. 포지션을 연 뒤에는 손절·익절·시간 초과 조건을 계속 감시하다가 자동으로 청산합니다.
6. 모든 거래를 데이터베이스에 기록하고, 중요한 이벤트는 텔레그램으로 알립니다.

**중요한 제약:**
- GPT(AI)는 **실시간 매매 결정에 쓰지 않습니다.** 주간 회고 보고서 작성에만 씁니다.
- 특정 코인(BTC/ETH 등 "보호 종목")은 봇이 **절대 거래하지 않습니다.** (→ [11장](#보호-종목-protected-symbols))
- 운영자가 손으로 개입하는 것을 전제로 만들지 않았습니다.

## 3. 기초 용어 사전

처음 보는 용어가 많을 수 있습니다. 이 표만 알면 나머지 문서를 읽을 수 있습니다.

| 용어 | 쉬운 설명 |
|---|---|
| **선물 (Futures)** | "미래 가격"에 대한 계약. 실제 코인을 사는 게 아니라 가격이 오를지/내릴지에 베팅하는 것. |
| **USDT-M 무기한 선물** | USDT(달러와 1:1 가치의 코인)로 정산되는, 만기일이 없는 선물. 바이낸스의 대표 선물 상품. |
| **롱 (Long)** | 가격이 **오르면** 이익을 보는 포지션. ("산다"는 느낌) |
| **숏 (Short)** | 가격이 **내리면** 이익을 보는 포지션. ("판다"는 느낌) |
| **포지션 (Position)** | 현재 열려 있는 거래. 롱이든 숏이든 청산하기 전까지 "포지션을 들고 있다"고 말함. |
| **레버리지 (Leverage)** | 빌린 돈으로 더 큰 금액을 거래하는 배율. 5배 레버리지 = 내 돈의 5배를 거래. **이익도 손실도 5배가 됨.** 이 봇은 최대 5배까지만 씀. |
| **마진 (Margin)** | 포지션을 열기 위해 묶어두는 보증금. 포지션을 닫으면 풀림. |
| **청산 (Liquidation / Close)** | 포지션을 닫는 것. 이익 실현(익절) 또는 손실 확정(손절). |
| **손절 (Stop Loss)** | 손실이 일정 수준에 도달하면 더 큰 손실을 막으려고 포지션을 닫는 것. |
| **익절 (Take Profit)** | 이익이 목표에 도달하면 포지션을 닫아 이익을 확정하는 것. |
| **레짐 (Regime)** | 시장의 "상태". 이 봇은 5가지로 분류: 상승추세(TREND_UP) / 하락추세(TREND_DOWN) / 횡보(RANGING) / 불확실(UNCERTAIN) / 고변동성(HIGH_VOL). |
| **미결제약정 (Open Interest, OI)** | 시장에 열려 있는 선물 계약의 총량. 급증하면 새 자금이 들어온 신호로 봄. |
| **펀딩비 (Funding Rate)** | 무기한 선물에서 롱과 숏이 서로 주고받는 수수료. 시장 쏠림을 보는 지표. |
| **테스트넷 (Testnet)** | 바이낸스가 제공하는 **가짜 돈** 연습장. 실제 돈이 안 들어감. 페이퍼 트레이딩용. |
| **페이퍼 트레이딩 (Paper Trading)** | 실제 돈 없이 모의로 매매해보는 것. 이 봇에서는 테스트넷에서 진짜 주문 흐름을 돌리는 것을 의미. |
| **드라이런 (Dry-run)** | 거래소에 주문 자체를 안 보내고, 봇 내부 동작과 DB 기록만 시험하는 모드. 페이퍼보다 더 가벼운 점검용. |
| **MDD (Max Drawdown)** | 자본이 고점 대비 최대 얼마나 떨어졌는지. 위험도 측정 핵심 지표. |
| **PF (Profit Factor)** | 총이익 ÷ 총손실. 1보다 크면 돈을 번 것. |
| **승률 (Win Rate)** | 전체 거래 중 이긴 거래의 비율. |
| **API 키 (API Key)** | 봇이 당신 대신 거래소에 접속하도록 해주는 "출입증". 절대 남에게 노출하면 안 됨. |
| **환경변수 / .env** | 봇에게 알려주는 설정값(키, 옵션 등)을 담는 파일. |
| **레짐별 게이트 (Gate)** | 신호가 들어와도 통과해야 하는 검문소들. 품질·리스크·비용 등 여러 게이트를 다 통과해야 거래함. |

## 4. 준비물

봇을 돌리기 전에 다음이 필요합니다.

### 4-1. 필수

- **Python 3.10 이상** — 프로그래밍 언어 실행 환경. [python.org](https://www.python.org)에서 설치.
- **바이낸스 API 키 2쌍**:
  - 테스트넷 키: [testnet.binancefuture.com](https://testnet.binancefuture.com) 가입 후 발급 (페이퍼용)
  - 실거래 키: [binance.com API 관리](https://www.binance.com/en/my/settings/api-management) (실전용 — 페이퍼 통과 후에만)
  - ⚠️ 두 키는 **완전히 별개**입니다. 서로 호환되지 않습니다.

### 4-2. 권장

- **텔레그램 봇** — 봇의 상태·거래 알림을 휴대폰으로 받기 위함.
  - 텔레그램에서 `@BotFather`에게 `/newbot` → 토큰 발급
  - `https://api.telegram.org/bot<토큰>/getUpdates`로 본인 chat ID 확인
- **OpenAI API 키** — 주간 회고 보고서 작성용 (월 ~$2). 없어도 봇은 정상 작동(보고서만 생략).
- **CoinMarketCap API 키** — 코인 시가총액 검증용 (무료 플랜으로 충분). 없어도 작동.

### 4-3. API 키 권한 설정 (중요)

거래소에서 API 키를 발급할 때 권한을 다음과 같이 설정하세요:

- ✅ **Enable Futures** (선물 거래) — 켜기
- ❌ **Enable Spot & Margin Trading** (현물 거래) — **끄기** (보호 자산 격리)
- ❌ **Enable Withdrawals** (출금) — **반드시 끄기** (보안)
- ✅ **IP 화이트리스트** — 봇을 돌리는 컴퓨터/서버 IP만 허용

## 6. 환경 설정 (.env 파일)

`.env` 파일은 봇의 모든 설정과 비밀 키가 들어가는 파일입니다. 프로젝트 루트에 있습니다.

> ⚠️ **`.env` 파일은 절대 다른 사람에게 보내거나 인터넷에 올리지 마세요.** API 키가 들어 있습니다. 이 파일은 `.gitignore`에 등록되어 git에 커밋되지 않습니다.

### 6-1. 설정 항목 전체 설명

| 항목 | 필수? | 설명 |
|---|---|---|
| `BINANCE_API_KEY` | 필수 | 실거래용 API 키 (`USE_TESTNET=false`일 때 사용) |
| `BINANCE_API_SECRET` | 필수 | 실거래용 API 시크릿 |
| `BINANCE_TESTNET_API_KEY` | 필수 | 테스트넷용 API 키 (`USE_TESTNET=true`일 때 사용) |
| `BINANCE_TESTNET_API_SECRET` | 필수 | 테스트넷용 API 시크릿 |
| `USE_TESTNET` | 필수 | `true` = 테스트넷(가짜 돈) / `false` = 실거래(진짜 돈) |
| `OPENAI_API_KEY` | 선택 | 주간 보고서용. 없으면 보고서만 생략됨 |
| `TELEGRAM_BOT_TOKEN` | 권장 | 텔레그램 알림 봇 토큰. 없으면 알림이 로그로만 남음 |
| `TELEGRAM_CHAT_ID` | 권장 | 알림을 받을 텔레그램 채팅 ID |
| `DB_PATH` | 선택 | 데이터베이스 경로를 **강제 지정**. 비워두면 자동 선택 (아래 6-2 참조) |
| `LOG_LEVEL` | 선택 | 로그 상세도. `INFO`(기본) / `DEBUG`(자세히) / `WARNING`(중요만) |
| `CMC_API_KEY` | 선택 | CoinMarketCap 키. 없으면 시총 검증만 생략 |
| `PROTECTED_SYMBOLS` | 선택 | 봇이 거래 못 하는 종목 목록. 비우면 기본값(BTC/ETH/HOLO/CFX) |
| `OPERATOR_ID` | 선택 | 운영자 식별자 (로그 추적용) |
| `ENVIRONMENT` | 선택 | 환경 표시: `development` / `paper` / `production` |

### 6-2. 데이터베이스 자동 선택 (중요)

`DB_PATH`를 **비워두면**, 봇은 `USE_TESTNET` 값에 따라 데이터베이스를 자동으로 분리해서 씁니다:

- `USE_TESTNET=true` → `data/bot.db` (테스트넷/페이퍼 데이터)
- `USE_TESTNET=false` → `data/bot_live.db` (실거래 데이터)

**왜 분리하나요?** 페이퍼 데이터와 실거래 데이터가 한 파일에 섞이면, 봇이 "초기 자본"이나 "최대 낙폭(MDD)" 기준을 잘못 계산해서 **안전장치가 제대로 작동하지 않습니다.** 그래서 자동으로 분리합니다.

`DB_PATH`에 값을 넣으면 그 경로를 강제로 씁니다(override). 특별한 이유가 없으면 비워두세요.

## 7. 실행 모드 3가지

봇은 3가지 모드로 돌릴 수 있습니다. **위험도 순서대로** 정리했습니다.

### 모드 A — 드라이런 (Dry-run): 가장 안전, 점검용

```powershell
$env:USE_TESTNET="true"; python main_7590.py --dry-run --duration 100
```

- 거래소에 **주문을 아예 안 보냅니다.** 봇 내부 로직과 DB 기록만 시험.
- 봇이 켜지는지, 모듈이 잘 조립됐는지, 에러가 없는지 점검할 때 씁니다.
- 실제 돈도, 가짜 돈도 안 움직입니다.

### 모드 B — 테스트넷 페이퍼 (Paper): 모의 실전

```powershell
$env:USE_TESTNET="true"; python main_7590.py
```

- 바이낸스 **테스트넷**(가짜 돈)에 **진짜로 주문을 보냅니다.**
- 체결·청산·손익이 모두 실제처럼 일어나지만 돈은 가짜입니다.
- **실전과 100% 동일한 코드 경로**입니다. 실전 전 검증은 이 모드로 합니다.
- 데이터는 `data/bot.db`에 쌓입니다.

### 모드 C — 실거래 (Live): 실제 돈

```powershell
$env:USE_TESTNET="false"; python main_7590.py
```

- 바이낸스 **실거래소**(binance.com)에 **실제 돈으로 주문을 보냅니다.**
- ⚠️ **페이퍼 8주 + 5대 기준을 통과하기 전에는 절대 쓰면 안 됩니다.** (→ [14장](#14-페이퍼--실전-전환-기준))
- 데이터는 `data/bot_live.db`에 쌓입니다.

> 💡 `.env`의 `USE_TESTNET` 값이 기본 모드를 정하므로, 위 명령에서 `$env:USE_TESTNET=...` 부분을 생략하면 `.env`에 적힌 값이 적용됩니다.

| 옵션 | 설명 |
|---|---|
| `--dry-run` | 거래소 주문을 보내지 않음 (DB 기록만). 붙이면 드라이런, 안 붙이면 실제 주문. |
| `--duration <초>` | 몇 초 동안 실행할지. `0`(기본값)이면 멈출 때까지 무한 실행. 예: `--duration 600` = 10분. |

### 8-3. 하트비트 (주기적 생존 알림)

봇은 일정 주기마다 "나 살아있어요" 상태 메시지를 텔레그램으로 보냅니다. 이걸 **하트비트**라고 합니다.

- 기본 주기: **1시간** (3600초)
- 주기 변경: 환경변수 `HEARTBEAT_INTERVAL_S`로 조정

```powershell
# 하트비트를 30분(1800초)마다 받기
$env:HEARTBEAT_INTERVAL_S="1800"; $env:USE_TESTNET="true"; python main_7590.py
```

하트비트 메시지에는 가동 시간, 루프 횟수, 현재 레짐, 미청산 포지션 수, 잔고, 직전 스캔 결과가 담깁니다. (→ [10장](#10-텔레그램-알림-읽는-법))

### 8-4. 봇이 켜졌는지 확인하는 법

봇을 켜면 콘솔에 로그가 흐릅니다. 정상이면 다음 순서로 메시지가 나옵니다:

1. `[Collector] 키 기반 클라이언트 생성 완료` — 거래소 연결됨
2. `[PairWhitelist] 보호 종목 4개 영구 차단` — 보호 종목 적용됨
3. `[MainBot] 초기화 완료` — 봇 조립 완료
4. `[Start] 초기 자본: wallet=$...` — 자본 조회됨
5. `[Main] 메인 루프 시작 (interval=30s)` — **본격 가동 시작**
6. 이후 30초마다 `[OIScanner] 스캔 완료...` 반복

텔레그램으로도 `🚀 봇 가동 시작` 메시지가 옵니다.

## 9. 봇이 내부에서 하는 일 (동작 원리)

봇이 "블랙박스"처럼 느껴지지 않도록, 내부 흐름을 풀어 설명합니다.

### 9-1. 시작 시퀀스 (켤 때 한 번)

봇을 켜면 다음을 순서대로 합니다:

1. **데이터베이스 초기화** — 거래 기록을 저장할 DB 준비 (이미 있으면 건너뜀)
2. **API 키 권한 검증** — 현물(Spot) 권한이 켜져 있으면 경고 (꺼야 함)
3. **초기 자본 기록** — 시작 시점 잔고를 DB에 저장 (MDD 계산 기준)
4. **보호 종목 알림** — 텔레그램으로 보호 종목 목록 전송
5. **페어 화이트리스트 갱신** — 거래 가능한 코인 목록 작성
6. **메인 루프 시작**

### 9-2. 메인 루프 (30초마다 반복)

봇이 켜져 있는 동안 30초마다 다음 검사를 합니다. 이걸 "레이어"라고 부릅니다:

| 레이어 | 하는 일 |
|---|---|
| **Layer 0 — 건강 체크** | 시스템 이상 점검. 심각하면(critical) 모든 포지션을 안전 청산하고 잠시 멈춤. |
| **자본 조회** | 현재 지갑/가용/마진 잔고를 확인 (CapitalManager). |
| **Layer 1+2 — 데이터·시장 분석** | BTC 캔들·펀딩비를 받아 **현재 레짐**(상승/하락/횡보/불확실/고변동)을 판단. |
| **포지션 관리** | 이미 열린 포지션의 손절·익절·시간초과 조건을 검사하고, 맞으면 청산. |
| **진입 차단 체크** | 레짐이 고변동성(HIGH_VOL)이거나 거시 이벤트(FOMC 등)가 임박하면 **신규 진입 금지**. |
| **Layer 3+4 — 신호·게이트** | 거래 후보 코인을 스캔 → 페어/OI/품질/리스크/사이징/비용 게이트를 차례로 통과시킴. 다 통과하면 진입. |
| **배치 작업** | 주간 보고서, 페어 목록 갱신 등 주기적 작업 실행. |
| **하트비트** | 설정 주기가 지났으면 상태 메시지 전송. |

### 9-3. 거래 하나가 성사되기까지 (게이트 통과 과정)

후보 코인이 발견돼도 다음 검문소를 **전부** 통과해야 실제로 진입합니다. 하나라도 막히면 거래 안 함:

1. **페어 화이트리스트** — 거래 허용 종목인가? (보호 종목이면 즉시 차단)
2. **OI 필터** — 미결제약정 흐름이 추세에 맞는가? (역추세면 위험 등급)
3. **품질 게이트** — 신호 품질 점수가 레짐별 기준 이상인가?
4. **리스크 매니저** — 일일 손실 한도, 연속 손실, 동시 포지션 수 등 위반 없는가?
5. **사이징** — 얼마를 걸지 계산 (Kelly 공식 기반, 보수적으로 축소). 가용 잔고를 넘으면 차단.
6. **CostGuard** — 수수료·슬리피지를 빼고도 기대값이 양수인가?
7. 전부 통과 → **TradeExecutor가 Post-Only 주문 전송**

이렇게 검문소가 많은 이유는 [1장](#1-먼저-읽어주세요-경고)의 철학 때문입니다 — 안 잃는 게 우선.

### 9-4. 참고: 기술적 한계 (현재 버전)

- **WebSocket 미구현** — 실시간 스트림 대신 REST API를 30초마다 폴링합니다. 정상 동작이지만 반응이 30초 단위입니다.
- **로그는 콘솔 전용** — 파일로 저장/회전(rotation)하는 기능은 아직 없습니다. 로그를 남기려면 직접 파일로 리다이렉트하세요. (→ [13장](#13-1-로그-보는-법))

## 11. 안전장치 (리스크 룰)

이 봇의 핵심은 "안전장치"입니다. 명세서 §9 RISK_RULES에 정의되어 있으며 **임의로 완화하면 안 됩니다.**

### 11-1. 주요 리스크 한도

| 항목 | 기본값 | 의미 |
|---|---|---|
| 거래당 리스크 | 자본의 0.5% | 한 거래에서 잃을 수 있는 최대치 |
| 일일 손실 한도 | 자본의 1.5% | 하루에 이만큼 잃으면 그날 거래 중단 |
| 최대 낙폭(MDD) 한도 | 자본의 15% | 누적 손실이 이만큼이면 봇 중단 |
| 동시 포지션 수 | 1개 (자본 $5천↑ 2개, $2만↑ 3개) | 한 번에 들고 있을 수 있는 포지션 개수 |
| 연속 손실 경고 | 3연패 | 3번 연속 지면 4시간 쿨다운 |
| 연속 손실 심각 | 5연패 | 5번 연속 지면 24시간 쿨다운 |
| 연속 손실 종료 | 7연패 | 7번 연속 지면 장기 중단 + 페이퍼 강제 복귀 |
| 최소 거래 잔고 | $100 | 잔고가 이 아래면 신규 거래 안 함 |
| 보존 최소 잔고 | $50 | 항상 남겨두는 금액 |

### 11-2. 레짐별 거래 제한

시장 상태(레짐)에 따라 거래 강도가 자동 조절됩니다:

| 레짐 | 진입 허용 | 최대 레버리지 | 하루 최대 거래 | 포지션 상한 |
|---|---|---|---|---|
| 상승추세 (TREND_UP) | ✅ | 5배 | 5회 | 자본의 10% |
| 하락추세 (TREND_DOWN) | ✅ | 5배 | 4회 | 자본의 10% |
| 횡보 (RANGING) | ✅ | 3배 | 1회 | 자본의 6% |
| 불확실 (UNCERTAIN) | ✅ | 3배 | 2회 | 자본의 5% |
| 고변동성 (HIGH_VOL) | ❌ **금지** | 0 | 0 | 0 |

### 11-3. 보호 종목 (Protected Symbols)

봇이 **절대 거래하지 않는** 종목들입니다. 운영자가 따로 보유·관리하는 자산을 봇이 건드리지 못하게 격리하는 장치입니다.

- 기본 보호 종목: **BTCUSDT, ETHUSDT, HOLOUSDT, LYNUSDT**
- 변경: `.env`의 `PROTECTED_SYMBOLS`로 지정 가능
- 이 규칙은 **다른 어떤 규칙보다 우선**합니다. 좋은 신호가 와도 보호 종목이면 무조건 차단.
- 계좌에 보호 종목 포지션이 이미 있어도 봇은 그것을 **열지도, 닫지도, 관리하지도 않습니다.** 운영자가 직접 관리해야 합니다.

### 11-4. 현물(Spot) 격리

봇은 **선물(Futures) 잔고만** 사용합니다. 현물 지갑은 절대 건드리지 않으며, 자본 계산에도 포함하지 않습니다. 그래서 API 키의 현물 권한을 꺼두라고 권하는 것입니다.

## 14. 페이퍼 → 실전 전환 기준

⚠️ **이 장은 가장 중요합니다.** 실제 돈을 넣기 전 반드시 거쳐야 하는 관문입니다 (명세서 §11-3).

### 14-1. 페이퍼 단계 (필수, 단축 불가)

- **환경**: 바이낸스 테스트넷 (`USE_TESTNET=true`, `--dry-run` 없이)
- **기간**: **최소 8주**
- **방식**: 실전과 동일한 코드로, 모든 결정 자동, 운영자 개입 금지

### 14-2. 실전 전환 5대 기준 (전부 만족해야 함)

8주가 끝난 시점에 다음을 **모두** 충족해야 실거래 전환이 가능합니다:

| # | 조건 | 측정 |
|---|---|---|
| 1 | 총 거래 ≥ 200건 | `trades` 테이블 개수 |
| 2 | 승률 ≥ 45% | 이긴 거래 ÷ 전체 |
| 3 | Profit Factor ≥ 1.2 | 총이익 ÷ 총손실 |
| 4 | 최대 낙폭(MDD) ≤ 10% | 자본 곡선 분석 |
| 5 | 룰 위반 0건 | 수동 개입·강제 청산·코드 핫픽스 횟수 |

**하나라도 미달이면 실전 전환 불가.** 4주 페이퍼 연장 후 재평가합니다.

### 14-3. 카운터 리셋 (8주가 처음부터 다시 시작되는 경우)

다음이 발생하면 8주 카운터가 **0부터 다시** 시작됩니다:
- 운영자가 손으로 개입함
- 거래(결정) 로직의 버그를 수정함

> 참고: 알림 기능(하트비트 등)처럼 결정 로직과 무관한 변경은 리셋 대상이 아닙니다. 하지만 가능하면 페이퍼 시작 **전에** 모든 변경을 마치세요.

### 14-4. 실전 전환 절차 (5대 기준 통과 후)

1. `.env`에서 `USE_TESTNET=false`로 변경
2. 자본은 **단계적으로** 입금 (처음엔 소액 — 명세서 권장 최초 $500)
3. 텔레그램 알림 채널 구독 확인
4. 비상 정지 방법 숙지
5. 자본의 50% 이상은 콜드월렛에 분리 보관

## 15. 자주 발생하는 문제 (트러블슈팅)

| 증상 | 원인 / 해결 |
|---|---|
| `ModuleNotFoundError: No module named 'binance'` | 라이브러리 미설치. `pip install -r requirements.txt` 실행. |
| `Invalid API-key, IP, or permissions` | ① API 키 권한에 Futures가 켜졌는지 ② IP 화이트리스트 ③ 테스트넷/실거래 키 혼용 여부 확인. |
| 봇이 켜지자마자 종료됨 | 콘솔의 `[Main] 봇 실행 중단:` 줄 확인. 대개 API 키 또는 `.env` 문제. |
| `초기 자본 DB 복원: $5000` 인데 실제 잔고가 다름 | DB 오염. 실거래는 `data/bot_live.db`(자동 분리)를 쓰는지 확인. `DB_PATH`가 강제 지정돼 있으면 비우기. |
| 텔레그램 알림이 안 옴 | `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` 확인. 없으면 알림이 로그로만 남음(정상). |
| `[Collector] start_ws 스텁` 경고 | 정상입니다. WebSocket 미구현이라 REST 폴링으로 동작합니다. |
| `[Security] Spot 권한 활성화 감지` | API 키의 현물(Spot) 거래 권한이 켜져 있음. 거래소에서 끄세요. |
| OpenAI API 에러 | 키 만료/크레딧 부족. 주간 보고서만 생략되고 봇은 계속 작동합니다. |
| `OIScanner ... 후보 0`만 계속 나옴 | 정상입니다. 진입 조건에 맞는 코인이 없을 뿐. 봇은 조건이 맞을 때만 거래합니다. |
| 봇을 껐는데 거래소에 포지션이 남아 있음 | 정상 동작입니다. 봇을 다시 켜거나 거래소 UI에서 직접 청산하세요. |
